# Перекомпонування панелей контролів + пошук у списках — Design

## Мета

1. Зменшити кількість окремих панелей у `.controls`, об'єднавши
   "Абонплата" з "Комісія продажу" та "Пальне" з "Параметри видобутку".
2. Використати вивільнене місце: панель "Місце розташування" стає вдвічі
   ширшою, а списки "Регіони" й "Сузір'я" всередині неї розташовуються
   поруч (дві колонки) замість стеком.
3. Додати пошук над довгими списками (Регіони, Сузір'я, Ресурси), щоб не
   доводилось довго скролити чекліст у пошуках потрібного пункту.

## 1. Перенесення "Абонплата" в "Комісія продажу"

Панель "Абонплата" (`<h2>Абонплата</h2>` + тумблер `#subscription-enabled`
+ поле `#subscription-millions`) прибирається з `index.html` як окрема
`.panel`. Її вміст переноситься в кінець панелі "Комісія продажу", після
поля `#commission-custom`, відділений горизонтальним роздільником
(`<hr class="panel__divider">`).

ID елементів (`subscription-enabled`, `subscription-millions`) не
змінюються — `app.js` шукає їх за тими самими ID, тож логіка
(`els.subscriptionEnabled`, `els.subscriptionMillions`,
`attachListeners`, `computeAndRender`) лишається без змін.

## 2. Перенесення "Пальне" в "Параметри видобутку"

Панель "Пальне" (`<h2>Пальне</h2>` + тумблер `#fuel-enabled` + поле
`#fuel-modules`) прибирається з `index.html` як окрема `.panel`. Її вміст
переноситься в кінець панелі "Параметри видобутку", після поля
`#drills-count`, відділений тим самим `<hr class="panel__divider">`.

ID елементів (`fuel-enabled`, `fuel-modules`) не змінюються — `app.js`
не потребує змін у цій частині.

Результат: замість 6 панелей у `.controls` лишається 4 — "Параметри
видобутку" (+ пальне), "Місце розташування", "Ресурси", "Комісія
продажу" (+ абонплата).

## 3. Розширення "Місце розташування" вдвічі + дві колонки

Панель "Місце розташування" отримує додатковий клас `panel--span2`:

```css
.panel--span2 {
  grid-column: span 2;
}
```

(`.controls` — це `grid-template-columns: repeat(auto-fit, minmax(12rem,
1fr))`, `span 2` коректно працює з auto-fit-сіткою.)

Всередині панелі два `.field`-блоки (Регіони, Сузір'я) загортаються у
новий контейнер `.panel__columns`:

```css
.panel__columns {
  display: grid;
  grid-template-columns: 1fr 1fr;
  gap: 0.6rem;
}
```

Обидва `.field` всередині `.panel__columns` отримують клас
`field--grow` (той самий клас, що зараз має поле "Ресурси для
видобутку"), щоб чекліст використовував додаткову вертикальну висоту
(`max-height: clamp(9rem, 24vh, 22rem)`) замість малого фіксованого
ліміту — це і дає "дві високі колонки".

## 4. Пошук над списками (Регіони, Сузір'я, Ресурси)

Над кожним із трьох чеклістів (`#region-select`, `#constellation-select`,
`#resource-select`) у `.checklist-label-row`, поруч з кнопками
"Всі"/"Жодного", додається текстове поле:

```html
<input type="search" class="checklist-search" data-checklist="region-select"
       placeholder="Пошук…" aria-label="Пошук: Регіони" />
```

### Поведінка

- Суто візуальний фільтр: приховує (`display: none` на `.checklist__item`)
  пункти, чий `.checklist__label` textContent не містить введений текст
  (case-insensitive substring, без урахування діакритики).
- Нічого не знімає з вибору — прихований пункт лишається checked/unchecked
  яким був.
- Кнопки "Всі"/"Жодного" продовжують діяти на **весь** список
  (включно з прихованими фільтром пунктами), а не лише на видимі —
  без зміни поточної поведінки `checklistValues`.
- `renderChecklistOptions` перебудовує `innerHTML` при: зміні регіону
  (`populateConstellationOptions`), довантаженні echoes-іконок
  (`refreshResourceIcons`/`populatePriceList`), скиданні фільтрів
  (`resetFiltersToDefault`). Після кожної такої перебудови фільтр
  повторно застосовується виходячи з поточного значення відповідного
  `input.checklist-search` (якщо там щось введено).
- Реалізація: одна функція `applyChecklistSearch(container)`, що читає
  сусідній `.checklist-search` за `data-checklist` і ховає/показує пункти;
  викликається (а) на `input`-подію пошукового поля, (б) одразу після
  кожного виклику `renderChecklistOptions` для контейнерів, що мають
  пошук.
- Скидання пошукового поля через "Скинути фільтри" (`filtersResetAll`)
  не потрібне окремо — `resetFiltersToDefault` вже перебудовує списки;
  пошукові інпути при цьому **не** очищаються автоматично (щоб не
  губити те, що людина шукала), фільтр просто застосується повторно до
  нового набору пунктів.

## Поза межами цього спека

- Фільтрація/чекліст по зіркових системах — не додається (підтверджено
  користувачем: потрібен лише пошук по вже наявних списках).
- Жодних змін у `src/*.mjs` (optimizer/economics/render/csv) — це суто
  UI-шар (`index.html`, `style.css`, `app.js`).

## Тестування

- `node --test src/*.test.mjs` — має пройти без змін (логіка
  розрахунків не чіпається).
- Ручна перевірка в браузері: розкладка (злиття панелей, ширина
  "Місце розташування", дві колонки), пошук у трьох списках, що
  комісія/абонплата/пальне досі правильно впливають на розрахунок після
  переміщення.
