# Ліміт кількості планет на ресурс — Design

## Мета

Дозволити користувачу обмежити, скільки планет у топ-N вибірці можуть
видобувати той самий ресурс — окремо для кожного ресурсу. Приклад мотивації:
не більше 1-2 планет з паливом (займає багато об'єму й швидко заповнює
склади), тоді як інші ресурси лишаються без обмежень.

## UI

У чеклісті "Ресурси для видобутку" (`#resource-select`) кожен пункт отримує
невелике числове поле поруч із назвою ресурсу:

- Порожньо (плейсхолдер "∞") = без ліміту (поточна поведінка).
- `min="1"` — 0 чи від'ємні значення не підтримуються (для повного
  виключення ресурсу вже є чекбокс фільтра).
- Клік/фокус у полі не перемикає чекбокс ресурсу — стандартна поведінка
  `<label>`, що огортає кілька form-контролів: клік на конкретному
  контролі (не самому `<label>`) адресується лише йому.
- Зміна значення перераховує результат по події `change` (як і інші
  числові поля в застосунку — кількість планет/бурів), і зберігається в
  localStorage.

## Алгоритм (`src/optimizer.mjs`)

Замінює пару `bestResourcePerPlanet` + `topNPlanets` однією функцією:

```js
selectTopPlanets(rows, resources, drills, priceKey, n, resourceLimits = {})
```

Кроки:

1. Порахувати дохід (`computeRowRevenue`) для **кожного** рядка (планета,
   ресурс) — не тільки для найкращого ресурсу планети, як робив
   `bestResourcePerPlanet`.
2. Відсортувати всі пари за доходом спадаючи (глобально, без прив'язки до
   планети).
3. Пройти список жадібно, підтримуючи множину вже обраних планет і
   лічильники обраних ресурсів:
   - планета вже обрана → пропустити рядок (одна планета — один ресурс);
   - `resourceLimits[row.resource]` заданий і лічильник цього ресурсу вже
     на межі → пропустити рядок;
   - інакше — додати планету з цим ресурсом до результату, інкрементувати
     лічильник ресурсу.
4. Зупинитись, коли зібрано N планет або список вичерпано.

Оскільки прохід іде по глобально відсортованому списку (а не
по-планетно), "запасний" вибір при вичерпаному ліміті природно враховує
пріоритет доходу серед **усіх** планет і ресурсів — а не лише
альтернативних ресурсів тієї самої планети, яка не пройшла через ліміт.

Без лімітів (`resourceLimits = {}`) результат ідентичний старій парі
функцій: перше входження кожної планети у відсортованому за доходом
списку — це і є її найприбутковіший ресурс, а стоп на N-й вибраній
планеті відтворює `topNPlanets`.

Якщо для планети немає резервного ресурсу (вичерпані ліміти по всіх її
рядках), вона випадає з вибірки — фінальний результат може містити менше
ніж N планет. Це узгоджується з наявною поведінкою "якщо даних
недостатньо — беремо скільки є, без помилки".

`bestResourcePerPlanet` і `topNPlanets` більше ніде не використовуються
(перевірено — лише `app.js` і тести), тож видаляються разом зі своїми
тестами; тести оновлюються під `selectTopPlanets`.

## Дані та стан (`app.js`)

- `resourceLimitValues(container)` — новий хелпер, аналогічний
  `checkedChecklistValues`, що зчитує значення числових полів-лімітів з
  DOM (`{ [resourceName]: number }`, лише для полів із заповненим
  значенням).
- `renderChecklistOptions` отримує додатковий опційний колбек
  `getLimit(value)` — якщо переданий, для кожного пункту рендериться
  `<input type="number">` з поточним значенням ліміту. Використовується
  лише для `#resource-select`; регіони/сузір'я — без змін.
- `computeAndRender()` зчитує `resourceLimitValues(els.resourceSelect)` і
  передає далі в `computeBestConstellationResult` → `selectTopPlanets`
  замість поточного виклику `bestResourcePerPlanet` + `topNPlanets`.
- Персистентність: ліміти зберігаються в тому самому об'єкті localStorage,
  що й фільтри (`savedFilters.resourceLimits`), і відновлюються разом з
  ними при завантаженні сторінки.
- Кнопка "Скинути фільтри" (`resetFiltersToDefault`) також скидає ліміти
  ресурсів (рендерить чекліст без значень лімітів) — вони концептуально є
  частиною фільтрації ресурсів.

## Що не змінюється

- `render.mjs` — форма об'єкта "планета" на виході `selectTopPlanets`
  ідентична попередній (`planetId`, `region`, ..., `resource`, `revenue`
  тощо), тож рендер таблиць і зведення без змін.
- `economics.mjs`, `csv.mjs` — без змін.
- `filterRows`, `computeRowRevenue` — без змін, використовуються як і
  раніше.

## Тестування

`src/optimizer.test.mjs`, нові тести для `selectTopPlanets`:

1. Без лімітів — результат збігається з попередньою поведінкою
   `bestResourcePerPlanet` + `topNPlanets` (топ-N за доходом, по одному
   найкращому ресурсу на планету).
2. Ліміт на ресурс вичерпано → наступна обрана пара (планета, ресурс) —
   та, що має найвищий дохід серед **усіх** ще не обраних валідних пар
   (може бути інша планета, а не обов'язково другий ресурс тієї самої
   планети, що впала).
3. Ліміт настільки жорсткий, що N планет неможливо набрати (немає
   резервних варіантів) → повертається менше ніж N, без помилки.
4. N перевищує кількість доступних варіантів навіть без лімітів →
   повертається все, що є (існуюча поведінка).

Ручна перевірка в браузері: виставити ліміт 1 для ресурсу з кількома
кандидатами серед топ-N, переконатись що результат відповідає
очікуванням і що ліміт зберігається після перезавантаження сторінки.
